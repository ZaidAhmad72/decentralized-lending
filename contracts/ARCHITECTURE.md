# Architecture Comparison: TypeScript vs Solidity

## Overview

This document maps the TypeScript service layer (Supabase) to Solidity smart contracts (Base).

## File Mapping

| TypeScript Service | Solidity Contract | Purpose |
|-------------------|-------------------|---------|
| `poolService.ts` | `LendingPool.sol` | Liquidity pool management |
| `loanService.ts` | `LoanManager.sol` | Loan lifecycle |
| `reputationService.ts` | `Reputation.sol` | Credit scoring |
| `walletService.ts` | Native ETH/ERC20 | Wallet operations |

## Function Mapping

### PoolService → LendingPool

| TypeScript Function | Solidity Function | Notes |
|---------------------|-------------------|-------|
| `depositToPool()` | `deposit(uint256)` | Returns shares minted |
| `withdrawFromPool()` | `withdraw(uint256)` | Burns shares, returns tokens |
| `poolBorrow()` | `borrow(uint256)` | Only callable by LoanManager |
| `poolRepay()` | `repay(uint256)` | Only callable by LoanManager |
| `getPoolStats()` | `getPoolStats()` | Returns (liquidity, borrowed, shares, available) |
| `getUserShares()` | `shares(address)` | Public mapping |
| `getUserShareValue()` | `getUserShareValue(address)` | Calculates token value of shares |

### LoanService → LoanManager

| TypeScript Function | Solidity Function | Notes |
|---------------------|-------------------|-------|
| `borrowFromPool()` | `createLoan(uint256, uint256)` | Returns loanId |
| `repayLoan()` | `repayLoan(uint256)` | Requires token approval |
| `checkAndMarkDefaulted()` | `liquidate(uint256)` | Callable by anyone |
| `getUserActiveLoan()` | `getActiveLoan(address)` | Returns loanId |
| `getUserLoans()` | `getUserLoans(address)` | Returns loanId array |
| N/A | `calculateRepaymentAmount(uint256)` | New helper function |

### ReputationService → Reputation

| TypeScript Function | Solidity Function | Notes |
|---------------------|-------------------|-------|
| `getReputation()` | `getReputation(address)` | Returns full struct |
| `getCreditScore()` | `getCreditScore(address)` | Returns score only |
| `getMaxLTV()` | `getMaxLTV(address)` | Returns LTV in basis points |
| `getCreditTier()` | `getCreditTier(address)` | Returns tier string |
| `recordLoan()` | `recordLoan(address, uint256)` | Only LoanManager |
| `recordRepayment()` | `recordRepayment(address, bool)` | Only LoanManager |
| `recordDefault()` | `recordDefault(address)` | Only LoanManager |

## Key Differences

### 1. Authentication

**TypeScript:**
```typescript
const userId = await supabase.auth.getUser();
```

**Solidity:**
```solidity
address user = msg.sender; // Wallet address
```

### 2. Permissions

**TypeScript:**
- Row-level security (RLS) in Supabase
- User ID from auth session

**Solidity:**
- `onlyOwner` modifier (admin functions)
- `onlyLoanManager` modifier (internal functions)
- `msg.sender` for user identification

### 3. Transactions

**TypeScript:**
```typescript
// Simulated transaction
const txHash = await simulateTransaction("deposit");
await supabase.from("transactions").insert({ tx_hash: txHash });
```

**Solidity:**
```solidity
// Real blockchain transaction
emit Deposited(msg.sender, amount, shares);
// Transaction hash generated by blockchain
```

### 4. Token Handling

**TypeScript:**
```typescript
// Update wallet balance in database
await supabase
  .from("profiles")
  .update({ wallet_balance: newBalance })
  .eq("id", userId);
```

**Solidity:**
```solidity
// Transfer actual ERC20 tokens
token.safeTransferFrom(msg.sender, address(this), amount);
```

### 5. Interest Calculation

**TypeScript:**
```typescript
const DAILY_RATE = 0.024; // 0.024%
const interest = amount * (DAILY_RATE / 100) * durationDays;
```

**Solidity:**
```solidity
uint256 constant DAILY_RATE_BP = 24; // 24 basis points
uint256 constant BP_DIVISOR = 1000000;
uint256 interest = (amount * DAILY_RATE_BP * durationDays) / BP_DIVISOR;
```

### 6. Error Handling

**TypeScript:**
```typescript
if (amount <= 0) throw new Error("Amount must be greater than 0");
```

**Solidity:**
```solidity
error ZeroAmount();
if (amount == 0) revert ZeroAmount();
```

## Security Enhancements in Solidity

### 1. Reentrancy Protection

```solidity
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";

function deposit(uint256 amount) external nonReentrant {
  // Safe from reentrancy attacks
}
```

### 2. Safe Token Transfers

```solidity
import "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";

token.safeTransferFrom(msg.sender, address(this), amount);
// Reverts if transfer fails
```

### 3. Access Control

```solidity
modifier onlyLoanManager() {
  if (msg.sender != loanManager) revert OnlyLoanManager();
  _;
}
```

### 4. Integer Overflow Protection

Solidity 0.8+ has built-in overflow checks:
```solidity
totalLiquidity += amount; // Reverts on overflow
```

## Gas Optimization

### Efficient Storage

```solidity
// Pack variables to save gas
struct Loan {
  address borrower;      // 20 bytes
  uint96 amount;         // 12 bytes (fits in same slot)
  uint32 durationDays;   // 4 bytes
  uint32 createdAt;      // 4 bytes
  uint32 dueDate;        // 4 bytes
  LoanStatus status;     // 1 byte
}
```

### Immutable Variables

```solidity
IERC20 public immutable token; // Set once in constructor, cheaper reads
```

### View Functions

```solidity
function getPoolStats() external view returns (...) {
  // No gas cost when called externally
}
```

## Frontend Integration Changes

### Before (Supabase)

```typescript
import { depositToPool } from "@/services/poolService";

const txHash = await depositToPool(userId, amountInETH);
```

### After (Smart Contracts)

```typescript
import { ethers } from "ethers";

const provider = new ethers.BrowserProvider(window.ethereum);
const signer = await provider.getSigner();
const lendingPool = new ethers.Contract(address, abi, signer);

// Approve tokens
await token.approve(lendingPoolAddress, amount);

// Deposit
const tx = await lendingPool.deposit(amount);
const receipt = await tx.wait();
const txHash = receipt.hash;
```

## Migration Strategy

### Phase 1: Parallel Operation
- Keep Supabase for user profiles/metadata
- Use smart contracts for financial operations
- Sync state between both systems

### Phase 2: Full Migration
- Move all financial logic to contracts
- Use Supabase only for caching/analytics
- Or replace with decentralized storage (IPFS, Ceramic)

### Phase 3: Decentralization
- Remove centralized dependencies
- Use The Graph for indexing
- IPFS for metadata storage
- ENS for user profiles

## Cost Comparison

### TypeScript (Supabase)
- **Pros:** Free tier, fast reads, flexible queries
- **Cons:** Centralized, requires trust, no true ownership

### Solidity (Base)
- **Pros:** Decentralized, trustless, true ownership, composable
- **Cons:** Gas costs, slower finality, less flexible queries

### Estimated Gas Costs (Base)

| Operation | Gas | Cost (at 0.5 gwei) |
|-----------|-----|-------------------|
| Deposit | ~100k | $0.02 |
| Withdraw | ~80k | $0.016 |
| Create Loan | ~150k | $0.03 |
| Repay Loan | ~120k | $0.024 |
| Liquidate | ~100k | $0.02 |

## Conclusion

The Solidity implementation provides:
- ✅ True decentralization
- ✅ Trustless operation
- ✅ Composability with other DeFi protocols
- ✅ Transparent, auditable logic
- ✅ User ownership of funds

While maintaining the exact same business logic as the TypeScript version.
